# gitleaks

[gitleaks](https://github.com/gitleaks/gitleaks) finds hardcoded secrets — API
keys, tokens, passwords and private keys — in code. It ships ~200 built-in
rules covering the major cloud and SaaS providers, and it can scan a working
tree, a whole git history (every commit, every branch), or a stream on stdin.
Findings are reported as JSON, CSV, SARIF, JUnit or a custom template, so it
drops into CI, a pre-commit hook, or a one-off audit equally well.

## What's included

- **gitleaks** — the binary. `gitleaks dir <path>` scans files and directories,
  `gitleaks git <repo>` scans commit history, and `gitleaks stdin` scans a
  piped stream. It exits **1** when leaks are found and 0 when the target is
  clean (configurable via `--exit-code`).

The archive also ships upstream's `LICENSE` and `README.md` alongside the
binary. The default rule set is compiled into the binary — no config file is
required to start scanning.

`gitleaks dir` and `gitleaks stdin` are fully self-contained. **`gitleaks git`
requires `git` on `PATH`** — it shells out to `git log -p` and exits 1 with
`could not create Git log cmd` if git is missing.

## Usage

```sh
# scan a directory tree, machine-readable report
gitleaks dir . --report-format json --report-path gitleaks.json
```

```sh
# scan the full git history of the current repository
gitleaks git .
```

```sh
# scan a stream
cat secrets.env | gitleaks stdin
```

Custom rules, allowlists and per-repo exclusions go in a `.gitleaks.toml`
(`--config`, `GITLEAKS_CONFIG`, or `<target>/.gitleaks.toml`), and a
`.gitleaksignore` file suppresses known findings by fingerprint.

## Install with ocx

```sh
ocx install ocx.sh/gitleaks/gitleaks
```

```sh
# or pin a specific version
ocx install ocx.sh/gitleaks/gitleaks:8.30.1
```
