# k9s

[k9s](https://github.com/derailed/k9s) is a terminal UI for Kubernetes. It
gives a live, continuously refreshed view of the resources in a cluster —
pods, deployments, services, nodes, CRDs — and lets you act on them without
composing a single `kubectl` invocation: describe, edit, delete, scale, port-
forward, shell into a container, or tail logs, all from keystrokes over the
resource you are looking at.

It reads the same kubeconfig `kubectl` does, honours the same contexts and
namespaces, and respects RBAC — a read-only user sees a read-only k9s. Aliases,
hotkeys, plugins, custom views and skins are configurable per user and per
context.

## What's included

- **k9s** — the binary. Run `k9s` to launch the UI against your current
  context, `k9s -n <namespace>` to scope it, `k9s -c <resource>` to land
  directly on a resource view, and `k9s --readonly` to disable every mutating
  command. `k9s info` prints where k9s keeps its configuration and logs;
  `k9s version` prints the build.

The archive also ships upstream's `LICENSE` and `README.md` alongside the
binary.

## Configuration

k9s stores its configuration under an OS-specific directory, which `k9s info`
will print for you. Both the configuration and the log location can be
relocated with environment variables:

```sh
export K9S_CONFIG_DIR="$HOME/.config/k9s"
export K9S_LOGS_DIR="$HOME/.local/state/k9s"
k9s info
```
