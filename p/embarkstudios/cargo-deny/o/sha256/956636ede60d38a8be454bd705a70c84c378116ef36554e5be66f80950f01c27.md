# cargo-deny

cargo-deny is a cargo plugin from [Embark Studios](https://github.com/EmbarkStudios)
that lints the whole crate graph of a Rust project against policy you write down
in a `deny.toml`. It is the tool teams reach for when "which licenses are we
actually shipping?" and "does anything in here have an open RUSTSEC advisory?"
have to be answered by CI instead of by hand.

Four check families, each independently configurable:

- **licenses** — every crate's license resolved against an SPDX allow/deny
  expression, including per-crate clarifications and confidence thresholds for
  licenses detected from file contents.
- **advisories** — the graph matched against the RustSec advisory database, with
  explicit ignore entries and yanked-crate detection.
- **bans** — duplicate versions, specific crates, wildcard dependencies and
  build-script/native-library skips.
- **sources** — where crates may come from: crates.io, allowed git hosts, allowed
  GitHub/GitLab orgs.

## What's included

- **cargo-deny** — the linter (`check`, `list`, `fetch`, `init`). Runs standalone
  or as `cargo deny …` once it is on `PATH`.

`cargo-deny check` reads the crate graph via `cargo metadata`, so it needs a
Rust toolchain on `PATH` alongside this package; `cargo-deny init` and
`cargo-deny --version` do not.
