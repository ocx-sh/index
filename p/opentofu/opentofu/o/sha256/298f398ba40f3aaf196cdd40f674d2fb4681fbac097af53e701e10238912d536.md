# OpenTofu

[OpenTofu](https://opentofu.org) is an infrastructure-as-code tool: you
describe cloud resources declaratively in HCL, and it computes and applies the
difference between that description and the real world. It is the
Linux-Foundation-hosted, MPL-2.0 community fork of Terraform, created when
Terraform moved to the Business Source License, and it remains
drop-in-compatible with the Terraform provider and module ecosystem and with
existing state files.

## What's included

- **tofu** — the CLI. `tofu init` prepares a working directory and installs
  providers, `tofu plan` shows the changes a configuration implies, and
  `tofu apply` makes them. `tofu fmt`, `tofu validate` and `tofu console`
  work on a configuration alone, with no provider, backend or network.

The archive also ships upstream's `CHANGELOG.md`, `LICENSE` and `README.md`
alongside the binary.

`tofu` is a single self-contained static binary. Providers are **not** bundled:
`tofu init` downloads them from the OpenTofu registry at
`registry.opentofu.org` into the working directory, so any command that reaches
a provider needs network access and a writable working directory.

## Usage

```sh
# format, then check a configuration without touching any provider
tofu fmt -recursive
tofu validate
```

```sh
# the normal loop
tofu init
tofu plan -out=tfplan
tofu apply tfplan
```

```sh
# evaluate an expression against the current module
echo 'max(1, 2, 3)' | tofu console
```

State lives in a backend (local file by default; S3, GCS, HTTP and others are
built in), and `TF_*` environment variables — `TF_VAR_name`, `TF_LOG`,
`TF_IN_AUTOMATION` — configure runs without editing the configuration.

## Install with ocx

```sh
ocx install ocx.sh/opentofu/opentofu
```

```sh
# or pin a specific version
ocx install ocx.sh/opentofu/opentofu:1.12.5
```
