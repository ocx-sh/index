# ko

ko builds a Go program into a container image and publishes it, with no
Dockerfile, no Docker daemon and no privileged socket. It compiles the binary
on the host, lays it over a small distroless base and pushes the result
straight to a registry — typically in a couple of seconds, and reproducibly,
because there is no build context to drift.

Its second half is Kubernetes-facing: `ko resolve` reads your YAML, replaces
every `ko://<import-path>` image reference with the digest of the image it just
built and published, and prints the resolved manifests. `ko apply` pipes that
into `kubectl apply` in one step, which makes the edit-build-deploy loop a
single command.

## What's included

- **ko** — the single static binary (`ko build`, `ko resolve`, `ko apply`,
  `ko create`, `ko delete`, `ko run`, `ko login`). No runtime dependencies.

A Go toolchain is required to *build* images; `ko resolve` on manifests without
`ko://` references, and `ko version`, need neither Go nor a network.
