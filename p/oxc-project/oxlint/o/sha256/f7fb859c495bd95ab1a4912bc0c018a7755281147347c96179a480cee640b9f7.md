# oxlint

`oxlint` is the linter of the [Oxc](https://oxc.rs) toolchain — a JavaScript and
TypeScript static-analysis tool written in Rust. It ships as a single
self-contained executable with no Node.js, npm or plugin install step, and
implements a large ESLint-compatible rule set across the `correctness`,
`suspicious`, `pedantic`, `perf`, `style` and `restriction` categories, plus
framework plugins (React, Vue, Jest, Vitest, Next.js, JSX-a11y, promise, node,
import, jsdoc, unicorn).

## ⚠ The command is named after its target triple

**Upstream ships each release archive containing a single executable named after
its own Rust target triple, not `oxlint`.** This package publishes upstream's
bytes under upstream's own name, so the command this package puts on `PATH` is:

| Platform | Command |
|---|---|
| `linux/amd64` | `oxlint-x86_64-unknown-linux-musl` |
| `linux/arm64` | `oxlint-aarch64-unknown-linux-musl` |
| `darwin/amd64` | `oxlint-x86_64-apple-darwin` |
| `darwin/arm64` | `oxlint-aarch64-apple-darwin` |
| `windows/amd64` | `oxlint-x86_64-pc-windows-msvc.exe` |
| `windows/arm64` | `oxlint-aarch64-pc-windows-msvc.exe` |

Alias it if you want the short name — `alias oxlint=oxlint-$(uname -m)-…` — or
invoke it through `ocx run`.

## What's included

One executable, named per the table above. No plugins, config files or shared
libraries: everything the linter needs is inside the binary.

## Usage

```bash
# Lint a directory using the default `correctness` category.
oxlint-x86_64-unknown-linux-musl src/

# Fail the build on any finding — `correctness` findings are warnings by
# default and exit 0 without this.
oxlint-x86_64-unknown-linux-musl -D correctness src/

# Machine-readable output for CI.
oxlint-x86_64-unknown-linux-musl -f json src/
oxlint-x86_64-unknown-linux-musl -f github src/     # GitHub Actions annotations
oxlint-x86_64-unknown-linux-musl -f sarif src/      # SARIF for code scanning

# Apply the safe autofixes.
oxlint-x86_64-unknown-linux-musl --fix src/
```

Configuration is an ESLint-v8-shaped `.oxlintrc.json` (JSON or JSONC), picked up
automatically or passed with `-c`.

## Platform notes

Linux is served by upstream's **statically linked** musl build, which requires
nothing of the host userland and therefore runs on glibc and musl systems
alike — verified in CI on `ubuntu:24.04`, `alpine:3.20` and `fedora:40`. The
separate `-gnu` builds upstream also publishes are deliberately not mirrored:
oxlint touches only the local filesystem, so neither of the usual reasons to
split the key (musl's DNS resolver, musl's allocator) applies — a 2000-file
lint measured 47 ms on the musl build against 49 ms on the gnu one.

Upstream additionally ships armv7, i686, ppc64le, riscv64, s390x and FreeBSD
artifacts. OCX's platform grammar has no way to express those, so they are out
of scope rather than missing.
