# kind

kind — "Kubernetes IN Docker" — creates and manages complete Kubernetes
clusters whose nodes are containers rather than machines or VMs. A cluster
comes up in tens of seconds on a laptop or a CI runner, which makes it the
standard way to test something *against* Kubernetes without paying for, or
waiting on, a real one.

It is the tool the Kubernetes project itself uses for conformance and CI, so a
kind cluster is a genuine cluster: real kubelets, real control plane, real
networking, driven by `kubeadm`. Cluster shape — node count, roles, port
mappings, feature gates, the Kubernetes version — comes from a declarative
`kind.x-k8s.io/v1alpha4` config file, and `kind load` pushes locally built
images straight into the nodes without a registry.

A container runtime (Docker, Podman or nerdctl) must be present on the host to
create a cluster; the binary itself has no other dependencies.

## What's included

- **kind** — the cluster manager (`create cluster`, `delete cluster`,
  `get clusters`/`nodes`/`kubeconfig`, `load docker-image`/`image-archive`,
  `export kubeconfig`/`logs`, `build node-image`).
